DLC_PRO — Avalonia MVVM 전환 작업

WinForms 버전(DlcProControl)의 장비 제어 기능을 Avalonia 12 + CommunityToolkit.Mvvm 구조로 옮기고, 화면과 아키텍처는 Avalonia BatchProcess(BatchProcess3)의 디자인 시스템을 그대로 따랐습니다. 작업 위치는 C:\Dev\DLC Pro\DLC_PRO입니다.

화면

아래 화면은 클라우드에서 앱을 헤드리스로 실행해 DLC pro 시뮬레이터(DlcSim)에 연결한 상태를 캡처한 것입니다. 실제 장비 값이 아니라 시뮬레이터 값입니다.

빌드 · 실행

  1. Visual Studio 또는 Rider에서 DLC_PRO\DLC_PRO.slnx를 엽니다. NuGet 복원 시 새로 추가한 패키지 2개(Microsoft.Extensions.DependencyInjection 10.0.0, System.IO.Ports 10.0.0)가 내려받아집니다.
  2. 빌드 후 실행하면 Laser 페이지가 열립니다. 상단 바에서 TCP/IP 주소(또는 USB COM 포트)를 넣고 연결을 누릅니다.
  3. 명령줄 옵션도 WinForms 버전과 같습니다.
DLC_PRO.exe --connect 192.168.0.100 --page scanlock
설정 파일 — %AppData%\DLC_PRO\settings.ini에 저장합니다. 처음 실행할 때 이 파일이 없으면 WinForms 버전의 %AppData%\DlcProControl\settings.ini(IP, 안전 설정, GHz/V 계수 등)를 읽어옵니다. 로그는 %AppData%\DLC_PRO\logs.

MVVM 구조

View는 표시와 입력만, ViewModel은 화면 상태와 명령만, 장비 통신과 안전 로직은 서비스/모델 계층에만 있습니다. ViewModel은 창·MessageBox·ScottPlot을 직접 다루지 않습니다.

새로 쓴 코드는 C# 약 4,700줄 + AXAML 약 3,600줄이고, Core(약 2,400줄)는 WinForms 버전과 같은 코드입니다.

설계 포인트

파라미터 행 = ViewModel + DataTemplate

페이지 ViewModel은 new NumberParamViewModel(dev, P.DlCcCurrentSet, "Set Current", "mA", 3, 0.1)처럼 행을 선언만 하고, View는 <ContentControl Content="{Binding CcCurrentSet}"/> 한 줄로 끝납니다. 라벨·입력·단위 모양은 App.axaml의 DataTemplate 하나가 정합니다.

확정된 값만 장비에 쓰는 입력란

Avalonia NumericUpDown은 글자를 칠 때마다 값이 바뀝니다(“150” 입력 중 1 → 15 → 150). ParamNumericUpDown은 스핀·Enter·수정 후 포커스 이동 때만 값을 내보내고, 수정 없이 포커스만 옮기면 쓰지 않습니다. Esc는 취소.

그래프는 PlotModel → PlotView

ViewModel은 곡선·마커·라벨 데이터(PlotModel)만 채우고 Invalidate()를 호출합니다. ScottPlot(AvaPlot) 그리기, 클릭/더블클릭, 오른쪽 메뉴(PNG·CSV 저장)는 PlotView 컨트롤이 맡습니다. 그래프 클릭은 SelectLockpointCommand로 전달됩니다.

갱신 주기와 페이지

DeviceService가 100 ms마다 Tick을 올리고, 보이는 페이지의 행만 캐시 값을 다시 읽습니다. 락 이벤트 기록·파워 추세·와이드스캔 자동 읽기는 페이지가 숨어 있어도 동작하도록 모든 페이지를 시작 시 만들어 둡니다. 스코프 스트리밍은 Scan & Lock이 보일 때만 켭니다.

안전 기능 (WinForms 버전과 동일하게 유지)

상단 AMP OFF / ALL OFF 버튼은 대화상자 오버레이 밖에 있어 확인 창이 떠 있어도 누를 수 있습니다. 대화상자 중에는 페이지와 사이드 메뉴 입력(키보드 포함)을 막고, 포커스를 대화상자의 취소 버튼으로 옮깁니다.
  • 증폭기 ON 전 조건 검사: 인터록 닫힘, 마스터 CC ON, seed 파워 ≥ 기준, 증폭기 TC ready, 최대 전류 확인 → 확인 대화상자 → 램프 스텝부터 설정 전류까지 단계 상승
  • 램프 중 Enable 버튼을 다시 누르면 램프 취소 후 OFF
  • 마스터 CC를 끌 때 증폭기가 켜져 있으면 “안전 순서” 확인 후 증폭기 먼저 OFF
  • 증폭기 전류: 휠 변경 금지, 스핀 연타는 600 ms 뒤 한 번만 전송, 최대 전류 초과 차단, 확인창 기준 이상 상승 시 확인
  • current-clip(최대 전류) 변경 시 확인, 값을 모르는 입력란은 비활성 (빈 칸 스핀으로 ±10⁹이 쓰이는 것 방지)
  • seed 감시(Watchdog) 차단 시 “안전 차단” 알림, 종료 시 증폭기 ON이면 [그대로 두고 종료 / 증폭기 OFF 후 종료 / 취소]

검증 중 찾아 고친 것

  • DataTemplateInclude는 Avalonia 12에 없음 → 파라미터 DataTemplate을 App.axaml에 직접 배치
  • ScrollViewer의 Padding이 측정 폭에서 빠지지 않아 카드 오른쪽이 잘림 → 안쪽 패널 Margin으로 이동
  • BatchProcess3 CheckBox 템플릿의 고정 글자 크기(16) → TemplateBinding으로 바꿔 13.5, 탭 헤더 여백 축소
  • 램프 중 Enable 토글이 비활성으로 묶이던 문제(AsyncRelayCommand 동시 실행) → 램프 취소 가능하게
  • 연속 쓰기/디바운스가 겹칠 때 화면이 옛 값으로 되돌아가던 문제, 빈 칸 스핀 문제, 대화상자 중 키보드 입력, 더블클릭 판정 시간(OS 설정 사용), 종료 순서(ShutdownRequested에서 먼저 정리하던 문제), 로그 파일 동시 쓰기

남은 일

  • Windows에서 첫 빌드: NuGet 복원 후 빌드 오류가 나면 오류 메시지를 알려 주세요. (Avalonia 컴파일 XAML 경로는 클라우드에서 같은 컴파일러로 검증했지만 MSBuild 작업 자체는 돌려보지 못했습니다.)
  • 템플릿에 있던 ViewModels\MainWindowViewModel.cs는 더 이상 쓰지 않습니다. 빌드에는 영향이 없으니 필요하면 지워도 됩니다.
  • 실제 장비에서는 증폭기 전류를 낮게 둔 상태로 증폭기 ON/램프/AMP OFF를 먼저 확인해 주세요. 시뮬레이터는 실제 TA의 seed/출력 보호 반응을 흉내내지 않습니다.
  • 레이저 헤드 사양서의 피에조 튜닝 계수(GHz/V)를 Scan & Lock → MHz 축 탭에 입력하면 두 페이지(Scan & Lock, Wide Scan)에 함께 적용됩니다.
