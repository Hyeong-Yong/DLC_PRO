# DLC_PRO 개선 및 추가 검토 — 2026-09-30

## 연결 실패

TCP 타임아웃·연결 거부·주소 오류를 사용자 경고로 표시하고, USB는 존재하지 않는 COM 포트와 다른 프로그램이 사용 중인 포트를 안내합니다. 실패 후 연결 상태를 정리하여 재시도할 수 있습니다. COM 선택값이 비어 있을 때도 예외 대신 안내합니다.

TCP 경고 문구는 “IP 주소의 장비를 찾을 수 없거나 응답이 없습니다”입니다. 타임아웃만으로 IP가 존재하지 않는다고 단정할 수 없으므로 전원·네트워크·방화벽 확인 안내를 함께 표시합니다.

Visual Studio에서 예외가 **throw될 때 중단**하도록 설정했다면, 앱이 처리하는 TimeoutException도 디버거가 먼저 중단 표시할 수 있습니다. 계속 실행하면 경고창 처리로 이어집니다. 이를 실제 프로세스 종료와 구분해야 합니다. 자동 검증에서는 경고 표시 후 동일 창에서 재연결 성공을 확인했습니다.

## IP 검색

TOPTICA Command Reference의 검색 방식에 따라 UDP 60010으로 `laserfinder`를 브로드캐스트하고 응답 출발지 IP와 장비 설명을 표시합니다. 검색 결과를 선택하면 TCP 주소에 반영됩니다. 자동 연결하거나 장비 IP를 변경하지 않습니다.

검색은 약 3초로 제한하고 중복 응답을 제거합니다. 같은 LAN에서 사용하며, 방화벽이나 TOPAS의 검색 포트 점유로 검색하지 못하면 안내합니다. USB COM 목록 갱신은 기존 기능을 사용합니다.

## 하드웨어 대시보드와 레이저 선택

시작 시 하드웨어 상태 화면을 표시합니다. TCP 또는 USB 연결 후 `laser1:type`, `laser2:type`을 읽어 존재하는 레이저를 표시합니다. 조회 오류를 임의로 “두 번째 레이저 없음”으로 취급하지 않으며, 지원하지 않는 파라미터 오류(-3)만 부재로 처리합니다.

대시보드에는 컨트롤러 이름·일련번호, 레이저 ID·라벨·제품명·Health·Emission·Laser·Scan·Lock·Power Lock 상태를 표시합니다. 값을 읽지 못한 상태는 OFF로 단정하지 않고 “—”로 표시합니다. 행을 클릭하면 선택한 레이저의 기존 제어 UI가 같은 창에 열립니다.

두 레이저는 하나의 TCP/USB 연결과 우선순위 명령 큐를 공유합니다. 파라미터·명령 이름의 `laser1:` 접두부만 대상으로 변환하며 문자열 값이나 Console의 수동 입력은 임의로 변경하지 않습니다. Console 빠른 명령은 선택한 레이저에 맞춥니다. 스코프, 레코더, 락, 그래프 이력과 안전 설정은 레이저별로 분리됩니다.

- 상단 AMP OFF: 감지된 모든 증폭기 OFF.
- 상단 ALL OFF: 각 레이저에서 증폭기 OFF 확인 후 마스터 OFF.
- Laser 페이지의 OFF: 선택한 레이저에 적용.
- 선택하지 않은 레이저도 활성화된 안전 감시를 수행.
- 레이저 전환 시 진행 중 전류 램프 취소.
- 연결 단절 시 선택 해제 후 대시보드로 이동. 연결 중 및 레이저 선택 전 제어 UI 비활성화.
- 다시 연결하면 레이저 개수를 재검사. 이전 장비의 레이저2 화면을 그대로 재사용해 제어하지 않음.
- 안전/주파수 설정: `settings.ini`와 `settings-laser2.ini`. 포트·통신 로그·스코프 최대 속도는 컨트롤러 공통 설정.

현재 구현 범위는 **한 DLC pro 컨트롤러의 레이저 1·2**입니다. 서로 다른 컨트롤러 두 대의 동시 연결이나 레이저 3·4는 포함하지 않습니다.

## 그래프 글꼴

ScottPlot 자동 글꼴 선택 대신 설치된 한글 지원 글꼴을 선택하고, 제목·X/Y축·오른쪽 축·범례·주석에 공통 적용합니다. Windows에서는 맑은 고딕을 우선 사용합니다. Stabilization, Scan & Lock, Wide Scan, Recorder를 Skia로 렌더링하여 확인했습니다. Wide Scan과 Recorder는 시뮬레이터 데이터 5,000점을 읽은 화면도 확인했습니다.

## 추가 발견 및 수정

1. Wide Scan이 오래된 캐시로 락/스캔 상태를 판단하던 경로: 시작 전 실시간 조회. 확인창 이후에도 같은 연결 세션인지 검사하고 락 상태 및 일반 스캔 OFF를 다시 확인한 뒤 시작.
2. 설정 파일의 `1e100` 같은 유한한 초대형 수치가 decimal 변환에서 시작 오류를 유발: 안전 설정 검증에서 복구.
3. 레이저2 화면에서 변경한 통신 설정이 다음 연결에 반영되지 않을 수 있는 문제: 컨트롤러 공통 설정으로 저장하고 각 Settings 화면에 동기화.
4. 레이저별 명령 뷰를 만들 때 불필요한 64 KiB 수신 버퍼가 반복 할당될 수 있는 문제: 연결 소유자만 버퍼 할당.
5. 증폭기가 없는 모델에서 ALL OFF가 오래된 모델 정보 때문에 거부될 수 있는 문제: 증폭기 파라미터 부재(-3) 시 모델을 직접 다시 조회하여 판단. 모델을 확인하지 못하거나 TA인 경우 마스터 OFF 차단 유지.

## 매뉴얼 근거

작업 폴더의 원본 문서를 확인했습니다(문서 파일은 이 저장소 밖에 있습니다).

- `Manual.pdf`, 6.3, p.149: Dual-Laser-Operation. 두 번째 레이저 제어에는 해당 하드웨어/라이선스 구성이 필요.
- 같은 문서 6.5~6.8, pp.150~156: TOPAS 대시보드, 상태 표시와 레이저별 메뉴/제어 화면.
- `1_TOPTICA DLC pro SOFTWARE_3.5.1/1_DOCUMENTATION/DLCpro-Command-Reference.pdf`, p.200: laser2 파라미터 트리.
- 같은 문서 4.4.2, p.293: UDP 60010 및 `laserfinder` 검색.

따라서 첨부하신 대시보드 → 레이저 선택 → 제어 화면 흐름은 매뉴얼에도 설명되어 있습니다. 이번 프로그램은 기존 Avalonia 디자인 안에서 이 흐름을 구현했습니다.

## 검증과 범위

최종 결과: **95개 검증 통과**(기존 통신·안전 62개 + UI/다중 레이저/검색/추가 회귀 33개). `dotnet build DLC_PRO.csproj -c Release --no-restore` 성공, **경고 0 / 오류 0**. 화면 캡처는 로컬 `Tests/artifacts/`에 생성했습니다.

저장소의 Tests 프로젝트로 기존 통신·안전 회귀 검증과 연결 경고, 검색 응답, 1/2대 감지, 레이저2 명령 분리, 전체 OFF, 설정 분리, 한글 글꼴, Wide Scan 확인 중 상태/연결 변경을 검사합니다. 실제 DLC pro나 레이저 출력은 작동시키지 않았습니다. 실제 USB 통신 및 LAN 브로드캐스트 응답, 장비 펌웨어별 지원 파라미터는 실장비 검증이 남아 있습니다.
