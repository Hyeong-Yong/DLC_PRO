# 장비 보호값 읽기 전용

사용자 요청에 따라 Maximum Current와 공장·교정 관련 값을 프로그램 내에서 변경할 수 없도록 고정했습니다. 설정 파일이나 관리자 모드로 이 보호를 해제하는 옵션은 없습니다.

## 화면

- Laser 1·2의 마스터/증폭기 Maximum Current를 입력 컨트롤에서 조회 컨트롤로 변경했습니다. 값 변경 확인창과 쓰기 동작을 제거했습니다.
- Stabilization의 외부 포토다이오드 Cal. Offset / Cal. Factor를 조회 전용으로 변경했습니다.
- System은 Normal(3)과 Read-only(4)만 선택할 수 있습니다. 일반 운전용 비밀번호 인증은 유지하며, Maintenance(2)·Service(1)·Internal(0) 권한 요청은 차단합니다.
- Console은 단일 `param-ref`, `param-disp`, 정해진 시스템 메시지 조회만 허용합니다. 쓰기·실행·권한 변경·복합 Scheme 표현식은 거부합니다. 조회 대상에 레이저1/2를 명시할 수 있습니다.
- Settings의 최대 증폭기 전류 이름을 **앱 전류 상한 (0=장비 제한)**으로 바꾸었습니다. 이 설정은 장비 제한값을 변경하지 않는 소프트웨어 상한입니다.

## 통신 계층

`HardwareAccessPolicy`는 검토된 일반 운전 파라미터/명령의 명시적 허용 목록을 사용합니다. 목록에 없는 항목은 기본적으로 변경 불가이므로, 알려진 공장값뿐 아니라 새 펌웨어의 미등록 설정도 쓰지 못합니다.

TCP·USB·레이저1·레이저2가 공통으로 사용하는 `DecofClient`에서 전송 전에 검사합니다. 일반/우선순위 큐, 서비스 직접 호출, 원시 Console 입력에도 적용됩니다. 이미 높은 장비 권한으로 연결되어 있어도 앱의 보호 검사는 생략되지 않습니다.

파라미터 이름에 다른 명령을 끼워 넣거나 `RawValue`로 실행식을 넣는 우회도 차단합니다. 모니터링 라인의 구독 이름과 권한 변경에도 검사를 적용합니다. 정책 위반은 전송 전 예외로 처리하므로 통신 연결을 고장 상태로 만들지 않습니다.

공장 설정 복원·로드·보정 실행처럼 간접적으로 값을 바꿀 수 있는 미허용 명령도 거부합니다. 전류/온도/피에조 운전 설정, 스캔, 락 PID, 락인 위상 조정, 레코더와 OFF 등 기존 일반 운전 기능은 유지합니다. 락인 Auto LIR는 공장 교정값을 쓰는 기능이 아닌 운전용 위상 최적화입니다(Command Reference p.76).

## 검증

전체 회귀 검증 **183개 통과**(보호 정책 83개, 기존 통신/안전 62개, UI 38개). Release 빌드 경고 0개, 오류 0개.

기록용 전송 계층으로 차단 요청이 실제 Write에 도달하지 않는지 확인합니다. 원시 쓰기, 복합식, 이름/인자 삽입, 권한 상승, 공장/교정값, 알 수 없는 명령과 두 레이저를 포함합니다. Headless UI에서는 숫자 입력 컨트롤이 없는지 확인하고, Console 변경 시도 후 시뮬레이터 제한값이 그대로인지 검사합니다. 실제 장비 설정은 변경하지 않았습니다.

## 적용 범위

이 보호는 배포된 DLC_PRO 프로그램 안에서 적용됩니다. TOPAS, 다른 TCP/USB 클라이언트, 장비 전면 패널 또는 소스를 수정해 만든 별도 프로그램의 동작까지 차단하는 장비 전체 잠금은 아닙니다. 기존에 실행 중인 프로그램은 종료하고 새로 빌드한 실행 파일을 시작해야 반영됩니다.
